# M1.44 — browser-side runtime tests for dynamic UI orchestration

M1.44 adds executable browser-side orchestration tests to complement the existing Go HTTP tests and static JavaScript asset checks.

## Scope

The new runtime suite executes the real `cmd/caching-tools/web/map-link.js` source under Node's built-in test runner and `vm` module. A small repository-local fake DOM supplies only the browser primitives required by the orchestration code.

No npm package installation, jsdom, Playwright, browser download or external runtime dependency is required.

## Qualified behavior

The runtime suite verifies:

- waypoint list selection is resolved by stable local ID when two waypoints have the same display name;
- path list selection retains route/track kind and resolves by kind + stable local ID;
- a ready DOM sentinel advances a dynamic-loader stage without adding another script;
- a script already marked `loaded` advances immediately;
- a script still `loading` advances only after its load event;
- a failed script is removed, recreated and can complete successfully on retry;
- repeated window-load orchestration does not duplicate quality/editor scripts while their loader state is already active.

## CI

GitHub Actions now provisions Node 24 and runs:

```sh
node --test tests/browser/*.test.mjs
```

in the same CI job as:

```sh
go test ./...
go vet ./...
go build ./...
```

This keeps the browser orchestration gate small while making loader and map/list behavior executable rather than relying only on string-presence assertions.

## Boundaries

The fake DOM is intentionally narrow and is not a replacement for future full-browser interaction testing. M1.44 targets the dynamic orchestration and stable-ID selection logic that previously had only static qualification.
