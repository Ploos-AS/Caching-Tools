# M1.48 — explicit ETRS89 / UTM CRS expansion

M1.48 hardens and expands the local datum/CRS converter for practical GPS use in Europe and the Nordic region.

## Scope

Caching Tools now treats the ETRS89 / UTM family as explicit EPSG CRSs instead of collapsing every `EPSG:258xx` input into one generic alias.

Supported projected CRSs are:

- EPSG:25828 through EPSG:25838
- corresponding ETRS89 / UTM zones 28N through 38N

The existing provider-neutral `ETRS89-UTM` alias remains supported for compatibility when a zone is supplied separately.

## Zone semantics

When an explicit CRS such as `EPSG:25832` is used, zone 32 is derived from the CRS itself. A separately supplied conflicting zone is rejected rather than silently overriding the CRS.

This removes the previous ambiguity where `normalizeCRS()` could turn an explicit EPSG code into a generic `ETRS89-UTM` value and thereby lose the encoded zone.

## UI

The browser UI now exposes a zone/EPSG selector for zones 28N–38N and sends explicit projected CRS names, for example `EPSG:25832`, to the API.

## Datum behavior

The existing WGS84 ↔ ETRS89 approximation policy is unchanged: geographic coordinates are treated as coincident for local GPS/hobby use and no epoch/plate-motion transformation is applied. ETRS89 geographic ↔ ETRS89 / UTM conversions use the GRS80 ellipsoid and are not marked approximate.

## Qualification

Tests cover:

- explicit `EPSG:25832` forward and inverse conversion without a separate zone;
- rejection of an explicit CRS/zone conflict;
- all supported EPSG:25828–25838 zone mappings;
- rejection of out-of-scope EPSG:25827 and EPSG:25839;
- compatibility of the generic `ETRS89-UTM` alias;
- static UI exposure of the explicit EPSG family.
