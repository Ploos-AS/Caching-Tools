# M1.33 — Field-note backup/import roundtrip

M1.33 completes a local backup/restore roundtrip for the persistent field-note logbook introduced in M1.31 and exported in M1.32.

## Scope

- Import the versioned JSON bundle emitted by M1.32.
- Require `format: "caching-tools-field-notes"` and `version: 1`.
- Validate every imported note before modifying the persistent store.
- Append imported notes to the existing local logbook in one atomic save.
- Allocate new local `note-*` IDs for every imported item.
- Preserve note content, status, type, occurrence time and soft waypoint/workspace links.
- Do not reuse source `id`, `created_at` or `updated_at` lifecycle metadata.
- Expose an explicit browser file picker and Import JSON backup action.

## API

`POST /api/field-notes/import`

Request body is the M1.32 bundle:

```json
{
  "format": "caching-tools-field-notes",
  "version": 1,
  "exported_at": "2026-09-08T06:30:00Z",
  "notes": []
}
```

Successful response:

```json
{
  "imported": 2,
  "notes": [
    {
      "id": "note-...",
      "title": "...",
      "occurred_at": "...",
      "created_at": "...",
      "updated_at": "..."
    }
  ]
}
```

Unsupported format/version, malformed JSON, or any invalid note returns HTTP 400.

## Atomicity

The full bundle is normalized and validated before the field-note store is locked and modified. If any note is invalid, no imported note is appended. A valid bundle is appended to the current store and written using the existing same-directory temporary-file + rename persistence path.

This is append/restore behavior, not destructive replacement. Existing field notes remain unchanged.

## Identity and references

Imported notes receive new local IDs. Source IDs and source create/update timestamps are intentionally ignored so backups can be restored repeatedly without identity collisions.

`waypoint_id` and `workspace_id` remain soft references. They are copied as values when present; M1.33 does not require matching local targets and does not rewrite those IDs.

## UI

The Field notes / logbook section now includes a Backup / restore control with a JSON file picker and **Import JSON backup** button. The browser parses the selected JSON and sends it to `/api/field-notes/import`. After success, the note list and active search/filter view refresh immediately.

## Persistence and privacy

- Persistent storage remains `/data/field-notes.json`.
- No new persistence file or schema migration is introduced.
- Import is an explicit user action.
- No external provider, account, API key, map service or network dependency is added.

## Qualification

M1.33 adds tests for:

- source IDs being replaced by new local IDs,
- source lifecycle timestamps not being reused,
- append behavior preserving existing notes,
- atomic rejection when one note in a bundle is invalid,
- HTTP success result,
- unsupported format/version rejection,
- browser import controls and endpoint wiring.
