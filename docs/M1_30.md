# M1.30 — Promote field markers to persistent waypoints

M1.30 lets a manual in-memory field marker be promoted explicitly into the existing persistent local waypoint store.

## Scope

The live-navigation session remains ephemeral. Only the selected marker is persisted, and only when the user explicitly promotes it.

A promoted marker uses the existing `POST /api/waypoints` endpoint and therefore becomes an ordinary waypoint under `/data/waypoints.json`.

## UI

The field-session controls now provide:

- a marker selector for promotion
- an editable waypoint name
- **Promote marker to waypoint**

The suggested waypoint name is derived from the marker type and its position in the session. The user may replace it before promotion.

## Data mapping

When a marker is promoted:

- marker latitude becomes waypoint latitude
- marker longitude becomes waypoint longitude
- marker type becomes waypoint type
- the selected waypoint name is used as waypoint name
- the marker note is preserved in the waypoint comment
- a provenance line containing the original marker timestamp is appended to the waypoint comment

No live-session breadcrumb data is persisted as part of marker promotion.

## Duplicate protection

After a successful promotion, the in-memory marker stores the created waypoint ID. The same session marker cannot be promoted again accidentally during that page session.

The marker remains part of the live session and remains available for GPX export as a GPX waypoint.

## Refresh behavior

After promotion Caching Tools refreshes:

- the persistent waypoint list
- field-navigation waypoint targets
- the local map when its refresh hook is available

This makes the new waypoint immediately usable without a page reload.

## Persistence and privacy

M1.30 does not make live sessions persistent. Breadcrumbs and unpromoted markers remain browser-memory-only. Only an explicitly promoted marker is written through the existing waypoint API.

## Compatibility

There is no new backend endpoint and no persistence-schema migration. M1.30 reuses the M1.3 waypoint model and API.
