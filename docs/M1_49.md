# M1.49 — live field-session map polish

M1.49 brings the current in-memory field session onto the existing local SVG map without adding persistence, map tiles or external services.

## Scope

The map overlay can now render:

- accepted live-navigation breadcrumbs;
- one polyline per recording segment;
- an explicit dashed visual gap between segments created by pause/resume;
- manual field markers with their marker type;
- a distinct visual state after a marker has been promoted to a persistent waypoint.

A `Live breadcrumbs / markers` control can hide or show the complete session overlay independently of the existing waypoint and route/track guidance overlays.

## Session semantics

M1.49 deliberately reuses the in-memory session state introduced in M1.25–M1.30. It does not create a second track model. Breadcrumbs rejected by the existing quality filter never enter `liveBreadcrumbs` and therefore never appear on the map. Pause/resume segment IDs remain authoritative, so the map never draws a normal breadcrumb polyline across a paused interval.

The dashed segment-gap line is only a visual indication of a recording break; it is not part of the recorded track and is not exported as a GPX segment.

Manual markers remain ephemeral until explicitly promoted. Promotion changes the marker's map appearance but keeps the existing persistent-waypoint workflow unchanged.

## Rerender behavior

The overlay hooks the existing accepted `addBreadcrumb()` path and marker renderer so successful session changes rerender the map overlay immediately. Base-map rerenders continue to rebuild the overlay through the existing `caching-tools:map-rendered` event.

## Local-first behavior

No new API endpoint, persistence format, browser permission or network dependency is introduced. All live-session overlay data stays in browser memory and uses the existing schematic local SVG projection.

## Acceptance

- live breadcrumbs render as separate SVG polylines by `recordingSegment`;
- pause/resume boundaries are visible and are not joined by the normal breadcrumb stroke;
- manual markers render with type labels;
- promoted markers have a distinct class/state;
- accepted breadcrumb additions rerender the overlay;
- marker rerenders update the overlay;
- the live-session layer can be disabled independently;
- existing waypoint and route/track overlays remain intact;
- Go tests, browser runtime tests, vet and build remain green.
