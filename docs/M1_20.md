# M1.20 — Visual route/track editing

M1.20 adds direct geometry editing on the existing local SVG map.

## Scope

- Select a saved route or track directly on the map.
- Render editable point markers for the selected path.
- Select a route/track point with mouse, touch/pointer or keyboard.
- Drag a point marker to a new map position and persist the new latitude/longitude.
- Delete the selected point using the existing path-edit API.
- Split a track segment at the selected point.
- Merge the selected track segment with the following segment.
- Refresh saved-path summaries and the local map after each edit.

## API extension

M1.20 extends `POST /api/paths/{id}/edit` with:

```json
{
  "operation": "set-point",
  "segment": 0,
  "point": 2,
  "latitude": 59.9139,
  "longitude": 10.7522
}
```

For routes, `segment` is ignored. Track edits address a point by segment and point index.

The API validates latitude/longitude bounds before persistence.

## Data compatibility

No persistent schema changes are required. Existing `/data/paths.json` files remain compatible.

Only the selected point's latitude/longitude are changed. Existing elevation and timestamp fields remain attached to that point.

## Map integration

`map.js` exposes a small local map interface containing:

- the current saved path objects,
- forward coordinate-to-SVG projection,
- inverse SVG-to-coordinate projection,
- client-pointer to current SVG-view conversion.

`map-editor.js` uses this interface and the existing M1.19 edit endpoint. No external map service, tile provider, CDN or API key is introduced.

## Qualification

M1.20 adds tests for:

- coordinate updates,
- invalid-coordinate rejection,
- elevation/timestamp preservation,
- map projection/editor assets,
- delete/split/merge/edit API references,
- pointer drag handling.
