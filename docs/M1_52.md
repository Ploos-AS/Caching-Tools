# M1.52 — field-session recovery hardening

M1.52 hardens the browser-local recovery mechanism introduced in M1.51.

## Stale-session policy

Recovered field sessions are now considered stale after seven days. A stale snapshot is removed from browser storage and is not offered for restore. This prevents an old field trip from being mistaken for the current session long after it was recorded.

The recovery status also reports age in human-friendly form such as `12 minutes ago`, `2 hours ago` or `2 days ago` instead of exposing only the raw timestamp.

## Storage limits

Recovery remains intentionally browser-local and best-effort.

Before writing to `localStorage`, the serialized snapshot is capped at 2 MiB. Snapshots above that limit are not written, and the UI reports the reason. This provides a predictable ceiling below common browser-local storage quotas while retaining the existing in-memory session.

If the browser rejects a write because storage is full or unavailable, recording continues normally and the UI shows a recovery-autosave warning. Recovery failure never rejects an otherwise accepted GPS breadcrumb or marker operation.

## Validation

Snapshots still require:

- schema version 1;
- valid breadcrumb and marker arrays;
- finite coordinates;
- valid point timestamps;
- a parseable `savedAt` timestamp;
- at most 10,000 restored breadcrumbs and 500 restored markers.

Malformed, unsupported or stale snapshots are removed rather than partially restored.

## Safety semantics

Recovery still does not automatically restart browser geolocation. Restore is explicit, and recovered coordinates remain an in-memory session until the user explicitly starts live GPS again.

## Qualification

Browser runtime tests cover:

- fresh recovery detection;
- human-readable recovery age;
- seven-day expiry;
- explicit restore without GPS restart;
- quota/storage-write failure while retaining in-memory data;
- the 2 MiB proactive snapshot ceiling;
- discard and malformed-snapshot behavior.

Go static UI qualification also checks the recovery age, expiry, size-limit and storage-failure paths.
