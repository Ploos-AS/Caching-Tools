# M1.19 — Local route/track editing

M1.19 adds persistent geometry editing for saved GPX routes and tracks.

## Operations

Routes support:
- delete a point
- move/reorder a point

Tracks support:
- delete a point within a segment
- move/reorder a point within a segment
- split a segment before a selected point
- merge a segment with the following segment

Edits are persisted back to `/data/paths.json`. Existing point elevation and timestamp data move with each point. Track segment boundaries remain explicit except when the user intentionally splits or merges them.

## API

`POST /api/paths/{id}/edit`

Request fields:
- `operation`: `delete-point`, `move-point`, `split-segment`, or `merge-segments`
- `segment`: zero-based segment index for tracks
- `point`: zero-based point index when required
- `target`: zero-based destination index for `move-point`

The response is the recomputed path summary. Invalid indices, empty resulting geometry and operations unsupported for the selected path kind return HTTP 400.

## UI

Saved routes/tracks gain an **Edit geometry** action. The local editor exposes the supported operations and refreshes both the saved-path list and local map after successful edits.

## Compatibility

No migration of `/data/paths.json` is required. The existing stored geometry representation is preserved, including its historical JSON field naming for embedded GPX points/segments.
