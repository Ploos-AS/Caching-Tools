# M1.25 — Live navigation session

M1.25 turns the existing field-navigation toolbox into a lightweight live field mode without adding persistent session data.

## Scope

The browser can start a live navigation session using the Web Geolocation API. Each accepted location update is sent to the existing `POST /api/navigation/field` endpoint, so all M1.24 waypoint/path guidance remains authoritative and local to the Caching Tools container.

The live UI continuously refreshes:

- waypoint distance and bearing
- route/track nearest-path and cross-track distance
- along-path progress and remaining distance
- next-point distance and forward bearing
- off-route / on-route / arrival guidance
- browser-reported GPS accuracy

## Session lifecycle

- **Start live navigation** creates one `navigator.geolocation.watchPosition` watcher.
- **Stop live navigation** clears that watcher with `clearWatch`.
- Leaving/hiding the page also clears an active watcher.
- Starting a new live session clears the previous breadcrumb list.
- Target, off-route threshold and arrival radius are read from the existing field-navigation form.

## Update serialization

GPS callbacks can arrive faster than the navigation API responds. M1.25 therefore keeps at most one navigation request in flight. If more positions arrive while a request is running, only the newest pending position is retained for the next request. This avoids request backlogs and stale guidance overwriting newer guidance.

A generation token prevents callbacks/results from a stopped or replaced live session from updating the UI.

## Breadcrumbs

Every processed live position is added to an in-memory breadcrumb list containing:

- timestamp
- latitude
- longitude
- browser-reported accuracy

The UI shows the latest 12 entries and the total point count. The list is capped at 1000 points by dropping the oldest point when needed.

Breadcrumbs are intentionally ephemeral:

- they are not sent to a persistence endpoint
- they are not written to `/data`
- they disappear on page reload or new live-session start
- they can be cleared manually

This keeps M1.25 useful for field awareness without silently creating a location-history database.

## Compatibility

- No persistent JSON schema changes.
- No migration is required.
- The existing `POST /api/navigation/field` contract is reused unchanged.
- Manual one-shot field navigation and `getCurrentPosition` remain available.
- Core navigation remains provider-neutral and requires no API key or external map service.

## Qualification

M1.25 static-asset tests verify that the live controls, `watchPosition`/`clearWatch` lifecycle, serialized update state, breadcrumb controls and ephemeral-data wording are present in the embedded UI.
