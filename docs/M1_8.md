# M1.8 — Saved path GPX export and rename

Status: implemented.

M1.8 makes persistent routes and tracks portable again after import and allows their display names to be changed without altering stored geometry.

## Included

- rename a saved route or track
- persist renamed path names in `/data/paths.json`
- export one saved route as GPX 1.1 `<rte>`
- export one saved track as GPX 1.1 `<trk>`
- preserve track segment boundaries during export
- preserve stored elevation and RFC3339 timestamps
- GPX output uses `Caching Tools` as creator
- browser Rename action for each saved path
- browser Export GPX action for each saved path
- no provider account, API key or network dependency

## API

- `PUT /api/paths/{id}` with JSON body `{ "name": "Sunday hike" }`
- `GET /api/paths/{id}/export`

The rename endpoint returns the updated path summary. Empty names are rejected.

The export endpoint returns `application/gpx+xml` with one route or one track and uses the internal path ID as a safe download filename.

## Round-trip behavior

Saved paths retain their original route points or track segments in `/data/paths.json`. Export reconstructs GPX from those stored objects rather than from summary statistics.

For tracks, segment boundaries are preserved exactly. Stored elevation values and timestamps are emitted on their original points. A generated GPX file is parsed again in the regression test to verify that the track survives a GPX 1.1 round trip.
