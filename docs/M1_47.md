# M1.47 — live-session GPX runtime qualification

M1.47 extends the executable browser-side qualification introduced in M1.44–M1.46 to the live field-session GPX exporter.

## Runtime coverage

The Node `node:test` suite now executes the real `field-quality.js` and `field-session.js` composition and verifies GPX behavior for:

- pause/resume recording boundaries becoming separate GPX `<trkseg>` elements;
- manual field markers becoming GPX `<wpt>` elements with type, timestamp and escaped notes;
- simplification being applied independently inside each recording segment rather than across paused gaps;
- correct exported point counts and simplification status reporting;
- marker-only sessions exporting valid waypoint-only GPX without requiring breadcrumb points.

## Marker-only fix

Before M1.47, the session wrapper delegated to the older breadcrumb exporter whenever `liveBreadcrumbs` was empty. A session containing manual markers but no breadcrumbs could therefore fail with `No breadcrumb points to export.`

M1.47 adds an explicit waypoint-only GPX path. If markers exist and breadcrumbs do not, the exporter returns a GPX 1.1 document containing the markers and no empty track. If neither markers nor breadcrumbs exist, the previous no-data behavior is preserved.

## Compatibility

Sessions with breadcrumbs retain the existing track representation and segment semantics. Manual markers are still emitted before the track as GPX waypoints. No persistence, backend API or GPX import behavior changes in this milestone.

## Qualification
