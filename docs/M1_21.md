# M1.21 — Datum / CRS conversion

M1.21 adds a small, explicit CRS layer for GPS and geocaching workflows without introducing an external geodesy dependency.

## Supported conversions

- WGS84 geographic (`EPSG:4326`) → ETRS89 geographic (`EPSG:4258`)
- ETRS89 geographic (`EPSG:4258`) → WGS84 geographic (`EPSG:4326`)
- WGS84 geographic → ETRS89 / UTM zone 28N–38N (`EPSG:25828`–`EPSG:25838`)
- ETRS89 geographic → ETRS89 / UTM zone 28N–38N
- ETRS89 / UTM zone 28N–38N → ETRS89 geographic
- ETRS89 / UTM zone 28N–38N → WGS84 geographic

## Accuracy model

ETRS89 / UTM projection uses the GRS80 ellipsoid. WGS84 projection code remains based on the WGS84 ellipsoid.

WGS84 ↔ ETRS89 geographic conversion is intentionally treated as an identity approximation suitable for ordinary hobby GPS/geocaching use. The response sets `approximate: true` and explains that no coordinate epoch or plate-motion transformation is applied. M1.21 therefore does not claim survey-grade or epoch-aware datum transformation accuracy.

## API

`POST /api/coordinates/crs`

Example WGS84 to ETRS89 / UTM zone 32N:

```json
{
  "source": "EPSG:4326",
  "target": "ETRS89-UTM",
  "latitude": "59.9139",
  "longitude": "10.7522",
  "zone": 32
}
```

The response identifies the concrete projected CRS, for example `EPSG:25832`, and returns easting/northing values.

## UI

The web UI exposes a local **Datum / CRS converter** with direction selection, explicit ETRS89 / UTM zone, geographic coordinate fields and projected easting/northing fields.
