# M1.50 — live-map viewport follow and fit

M1.50 adds explicit viewport controls for live field use while preserving manual map navigation as the default.

## Scope

The local SVG map now exposes safe viewport helpers and the overlay UI adds:

- `Follow GPS position`, disabled by default;
- `Fit current session`, an explicit one-shot action covering current breadcrumbs and manual markers.

## Follow semantics

Follow mode recentres the existing viewport on the current field-navigation coordinate after a successful navigation update. It preserves the current zoom level. It is opt-in and can be disabled immediately, so manual pan/zoom remains authoritative unless the user explicitly requests following.

Enabling follow performs one immediate recenter using the current coordinate when available. Failed navigation calls do not recenter the map.

## Fit-current-session semantics

The fit action projects all current in-memory breadcrumbs and manual field markers and fits a padded viewport around them. It does not include unrelated saved waypoints/routes/tracks, does not alter session data and does not enable follow mode.

With no current session points the action is a no-op.

## Map API

`window.cachingToolsMap` now exposes narrow viewport helpers:

- a copy of the current `view`;
- `setView(view)`;
- `centerViewOn(projectedPoint)`;
- `fitProjectedPoints(projectedPoints)`.

These reuse the existing viewBox and padded-bounds implementation rather than introducing a second viewport model.

## Acceptance

- follow is off by default;
- successful navigation recentres only while follow is enabled;
- follow preserves current viewport width/height;
- disabling follow restores normal manual viewport behavior;
- fit-current-session includes breadcrumbs and manual markers;
- empty sessions do not disturb the viewport;
- browser runtime tests cover follow on/off and session fitting;
- Go tests, browser runtime tests, vet and build remain green.
