# M1.4 — GPX 1.1 waypoint import/export

M1.4 adds standard GPX waypoint exchange to the local waypoint toolbox.

## Scope

- Import GPX 1.1 `<wpt>` elements into the local waypoint store.
- Export all locally saved waypoints as GPX 1.1.
- Preserve waypoint name, comment/description and type where possible.
- Validate coordinates before changing persistent state.
- Keep import atomic: if any imported waypoint is invalid, none are written.
- Keep the feature local-first with no provider account, API key or network dependency.

Tracks (`<trk>`) and routes (`<rte>`) are intentionally deferred to a later milestone.

## API

### Import

`POST /api/gpx/waypoints/import`

Body: GPX 1.1 XML. The endpoint returns JSON containing the number of imported waypoints and their local waypoint representations.

The importer accepts the standard GPX 1.1 namespace and also tolerates namespace-less GPX 1.1 documents for interoperability. Other explicit namespaces and GPX versions are rejected.

### Export

`GET /api/gpx/waypoints/export`

Returns `application/gpx+xml` with a download filename of `caching-tools-waypoints.gpx`.

## Field mapping

- `<wpt lat>` → waypoint latitude
- `<wpt lon>` → waypoint longitude
- `<name>` → waypoint name
- `<cmt>` → waypoint comment
- `<desc>` → comment fallback when `<cmt>` is absent
- `<type>` → waypoint type
- `<sym>` → type fallback when `<type>` is absent

Unnamed GPX waypoints receive a deterministic import label such as `GPX waypoint 2`.

## Persistence

Imported waypoints use the existing M1.3 store under `/data/waypoints.json` (or `CACHING_TOOLS_DATA_DIR`). Bulk import is written in one store update after the whole GPX document has passed validation.
