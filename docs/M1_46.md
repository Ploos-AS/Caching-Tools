# M1.46 — live field-session browser runtime qualification

M1.46 extends the dependency-free Node browser runtime suite to execute the real `field-quality.js` and `field-session.js` scripts together in one VM context.

This matters because the live-session layer wraps the quality-filtered breadcrumb function. The qualification therefore tests their composition rather than isolated helper logic.

## Runtime coverage

`tests/browser/field-session.test.mjs` verifies:

- breadcrumb rejection when GPS accuracy exceeds the configured maximum;
- breadcrumb rejection when movement is below the configured minimum distance;
- accepted breadcrumb accounting;
- pause preventing breadcrumb recording while navigation state remains available;
- resume starting a new recording segment;
- segment IDs attached to accepted breadcrumbs;
- session statistics excluding distance and moving time across pause boundaries;
- manual markers using the current field coordinate;
- custom marker types and notes;
- manual marker promotion through the real waypoint POST workflow;
- provenance text added to promoted waypoint comments;
- waypoint/field-target/map refresh after successful promotion;
- new live-session start resetting markers, pause state, recording segment and quality counters.

## Harness

The tests use Node's built-in `node:test`, `vm` and a small local fake DOM. No npm packages, external browser downloads or network access are required.

The fake DOM provides only the controls and DOM operations needed by the production scripts. Form control defaults that matter to behavioral semantics are set explicitly by the harness rather than inferred from HTML text.

## CI

The existing GitHub Actions `Browser runtime tests` gate runs all files matching:

```sh
node --test tests/browser/*.test.mjs
```

M1.46 therefore joins the loader/map-link and map-overlay runtime qualifications without adding a new dependency-management layer.
