# M1.42 — stable-ID map/list linkage hardening

M1.42 removes name- and visible-text-based linkage between the interactive SVG map and the waypoint/path lists.

## Problem

Before M1.42, a map selection tried to find the corresponding list row by comparing rendered text. Two waypoints with the same name, or two route/track objects with the same display name, could therefore highlight the wrong row.

## Stable linkage

`map-link.js` now annotates rendered list rows with stable local object identity:

- `data-map-id` contains the local waypoint/path ID;
- `data-map-kind` contains `waypoint`, `route` or `track`.

The annotation source is the same local `/api/waypoints` and `/api/paths` data used to render the lists. A `MutationObserver` schedules re-annotation after CRUD-driven list rerenders.

A `caching-tools:map-select` event is resolved only by `kind + id`. Names, comments, summary text and visible formatting are no longer part of selection identity.

If a selection arrives before a list has been annotated, the linkage performs one annotation refresh and retries the stable-ID lookup.

## Compatibility

This is browser-only hardening. It introduces no persistence, API or data-schema changes and does not alter map selection events, waypoint/path IDs or field-navigation behavior.

## Acceptance

- waypoint and path rows receive stable ID/kind metadata;
- annotations refresh after list child changes;
- map selection uses only ID and kind;
- duplicate display names cannot influence which row is selected;
- the old `startsWith(name)` / formatted-text matching path is absent;
- Go tests, vet and build remain green.
