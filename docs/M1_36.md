# M1.36 — Field-note attachments

M1.36 adds explicit local file attachments to persistent field notes without changing the existing `field-notes.json` schema.

## Storage

Attachment files are stored below:

```text
/data/field-note-attachments/<note-id>/
```

Each attachment has:

- a generated `att-*` ID
- a binary `.bin` payload
- a `.json` metadata sidecar
- original sanitized filename
- detected content type
- byte size
- UTC creation timestamp

Files and metadata are created with owner-only permissions where applicable. Deleting a field note also removes its attachment directory.

## Limits and validation

The maximum attachment size is **10 MiB per file**.

The server inspects the uploaded bytes with Go's content-type detector instead of trusting the browser-provided MIME type. The allowlist covers common local field material:

- JPEG, PNG, WebP and GIF images
- PDF
- plain text
- JSON / CSV when detected as an allowed textual type
- GPX / XML when detected as an allowed XML/text type

Empty files and unsupported detected content types are rejected. Attachment filenames are reduced to a basename, length-limited, and never used as storage paths. Attachment IDs from URL paths are also validated before filesystem access to prevent path traversal.

## API

For an existing field note:

```text
GET    /api/field-notes/{id}/attachments
POST   /api/field-notes/{id}/attachments
GET    /api/field-notes/{id}/attachments/{attachment_id}
DELETE /api/field-notes/{id}/attachments/{attachment_id}
```

Upload uses `multipart/form-data` with one field named `file`.

Downloads use `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`.

## UI

The **Field-note attachments** tool lets the user:

- select a persistent field note
- choose and upload a file
- see filename, detected type, size and upload time
- download an attachment
- delete an attachment
- refresh the attachment list

The note selector refreshes when the field-note list changes. When a waypoint is selected on the local map, the attachment tool can follow the first field note linked to that waypoint if one exists.

## Privacy and offline behavior

Attachments are local-only. Caching Tools does not upload them to any external service and does not require a provider account, API key, map service or CDN.

M1.36 does not add attachment data to field-note JSON backup bundles yet. Backup/export of binary attachments is intentionally left for a later, separately versioned milestone.

## Qualification

M1.36 adds Go tests for:

- attachment store create/list/get/delete
- filename sanitization
- content-type rejection
- empty and oversized upload rejection
- HTTP multipart upload
- attachment listing
- byte-for-byte download
- `nosniff` response hardening
- missing-note handling
- cascade cleanup when a field note is deleted
- static UI and loader integration
