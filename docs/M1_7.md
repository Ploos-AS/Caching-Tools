# M1.7 — Persistent tracks and routes

Status: implemented.

M1.7 turns GPX route/track inspection into reusable local data. Imported routes and tracks are stored independently from waypoints and remain available after container recreation.

## Included

- persist GPX 1.1 routes and tracks under `/data/paths.json`
- preserve full route point sequences
- preserve track segment boundaries
- preserve elevation and timestamp data for track points
- validate the complete GPX route/track set before persistence
- atomic JSON file replacement
- list saved routes/tracks with current computed summaries
- retrieve a saved path with full geometry
- delete saved paths
- web UI to save tracks/routes from the selected GPX file
- web UI list of saved route/track summaries
- no provider account, API key or network dependency

## APIs

- `POST /api/gpx/paths/import` — validate and persist all routes/tracks in a GPX 1.1 document
- `GET /api/paths` — list saved route/track summaries
- `GET /api/paths/{id}` — retrieve the complete stored route/track object
- `DELETE /api/paths/{id}` — delete one saved route/track object

The GPX inspector and M1.6 track statistics remain available through `POST /api/gpx/inspect`.

## Persistence model

Waypoints remain in `/data/waypoints.json`.

Routes and tracks are stored in `/data/paths.json`. A route stores its ordered point list. A track stores its ordered list of GPX track segments, and every segment stores its complete ordered point list. Elevation values and timestamps are retained when present.

The import validates every route and track before acquiring the store lock. The existing file is then loaded once, all imported objects are appended, and the new collection is written through a same-directory temporary file followed by rename. An invalid item therefore prevents the whole path import from being persisted.

## Scope decisions

M1.7 intentionally does not deduplicate repeated GPX imports. Re-importing the same file creates new saved objects. This keeps import semantics predictable and defers identity/deduplication policy until there is a richer track editor/library model.

Route/track editing and GPX export are also deferred. The complete point data is retained so those features can be added without another source import.
