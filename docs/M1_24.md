# M1.24 — Route deviation and arrival guidance

M1.24 extends the local field-navigation flow with explicit deviation and arrival status.

## Scope

- configurable off-route threshold, default 50 m
- configurable arrival radius, default 20 m
- waypoint `go-to` / `arrived` status
- path `on-route` / `off-route` / `next-point-arrival` / `arrived` status
- back-on-track guidance when cross-track distance exceeds the configured threshold
- field UI controls for both thresholds
- no new persistent schema
- no provider, API key or external network dependency

## API

Existing endpoint:

`POST /api/navigation/field`

Optional request fields:

```json
{
  "off_route_threshold_m": 50,
  "arrival_radius_m": 20
}
```

The response now always includes a `guidance` object containing:

- `status`
- `message`
- `off_route`
- `arrived`
- `off_route_threshold_m`
- `arrival_radius_m`

For a saved path, cross-track distance is compared with `off_route_threshold_m`. When off route, the existing target/bearing values point to the nearest path position, giving a simple back-on-track instruction.

Path arrival takes precedence over deviation when the remaining along-path distance is within the arrival radius. Reaching the next point within the configured radius is exposed separately as `next-point-arrival`.

## Validation

Threshold values must be finite positive numbers. Existing waypoint and route/track navigation behavior remains compatible when threshold fields are omitted.
