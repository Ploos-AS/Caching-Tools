# M1.37 — attachment-aware field-note backup / restore

M1.37 adds a portable ZIP archive for persistent field notes and their local attachments.

## Archive format

`GET /api/field-notes/archive` returns `application/zip`.

The archive contains:

- `manifest.json` with format `caching-tools-field-note-archive`, version `1`
- field-note metadata in the manifest
- attachment metadata in the manifest
- attachment bytes as separate `attachments/*.bin` ZIP entries

Binary attachment data is deliberately not embedded as base64 in the normal field-note JSON format.

## Restore

`POST /api/field-notes/archive` accepts the raw ZIP body and appends the restored objects to the local stores.

Restore behavior:

- the entire ZIP structure and manifest are validated before import
- unsafe paths, duplicate entries and unreferenced ZIP entries are rejected
- total expanded archive size is limited to 128 MiB
- each attachment is still limited to 10 MiB
- filenames are sanitized again
- attachment MIME type is re-detected from the restored bytes and checked against the M1.36 allowlist
- all field-note requests are normalized and validated before persistent changes
- restored field notes receive new local `note-*` IDs
- restored attachments receive new local `att-*` IDs
- source create/update timestamps are not restored
- occurrence time, title/body/status/type and waypoint/workspace soft references are preserved
- existing field notes and attachments are not overwritten
- if attachment creation fails after notes have been created, the newly created restore set is rolled back on a best-effort basis

## UI

The web UI adds **Field-note archive backup / restore** after the attachment tool:

- **Download ZIP backup**
- ZIP file selection
- **Restore ZIP backup**
- restore result with imported note and attachment counts

After a successful restore, the field-note list, attachment view, dashboard and map waypoint logbook are refreshed when those hooks are available.

## Security / limits

The archive reader rejects path traversal / ZIP-slip style paths, duplicate entry names, unexpected unreferenced files, oversized manifests, per-file attachment limit violations and archives expanding beyond the global limit. Restored attachment bytes go through the same server-side MIME sniffing used by ordinary uploads.

M1.37 does not change `field-notes.json`, does not introduce external services, and keeps all backup/restore processing local to Caching Tools.
