# M1.3 — Local waypoints

Status: implemented.

M1.3 adds a local waypoint collection for geocaching and general GPS use. It is intentionally provider-independent and persists under `/data` so the same data survives container recreation.

## Features

- Create a waypoint with name, coordinate, optional type and optional comment.
- Accept DD, DMM or DMS latitude/longitude through the existing coordinate parser.
- List locally stored waypoints.
- Edit existing waypoints.
- Delete waypoints.
- Render saved coordinates using the existing DD/DMM/DMS formatter.
- Persist records atomically in `/data/waypoints.json`.
- Web UI for create, edit, list and delete.
- JSON API suitable for future GPX import/export.

## API

- `GET /api/waypoints`
- `POST /api/waypoints`
- `PUT /api/waypoints/{id}`
- `DELETE /api/waypoints/{id}`

Waypoint writes accept:

```json
{
  "name": "Trailhead",
  "latitude": "N 59 54.834",
  "longitude": "E 10 45.132",
  "type": "trailhead",
  "comment": "Private field note"
}
```

Responses include the normalized point in DD, DMM and DMS plus creation/update timestamps.

## Persistence

The default data directory is `/data`. It can be overridden with `CACHING_TOOLS_DATA_DIR`, primarily for testing or custom deployments.

The current storage backend is a small JSON file. The HTTP contract deliberately does not expose the storage implementation, so a later SQLite migration can preserve the same API.

## Acceptance criteria

- [x] Waypoints are local-first and require no provider account or API key.
- [x] Waypoints persist under `/data`.
- [x] Create/list/update/delete are supported through JSON APIs.
- [x] The web UI exposes the full CRUD workflow.
- [x] Coordinate validation reuses the established DD/DMM/DMS parser.
- [x] Tests exercise persistent create/list/update/delete behavior.
