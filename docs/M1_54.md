# M1.54 — field-session bundle forward compatibility

M1.54 establishes an explicit migration model for portable field-session JSON bundles so future schema changes do not strand older exports.

## Current bundle version

The current portable field-session bundle version is `2`.

Version 2 keeps breadcrumbs and markers under `session` and groups recording state under:

```json
"recording": {
  "paused": false,
  "segmentID": 0
}
```

New exports are always written as the current version.

## Version 1 compatibility

M1.53 bundles used version 1 with `paused` and `segmentID` directly under `session`.

M1.54 includes an explicit `v1 -> v2` migration. Importing a valid v1 bundle:

- preserves breadcrumbs and recording-segment IDs;
- preserves manual markers and marker metadata;
- moves pause/segment state into the v2 `recording` object;
- preserves existing metadata;
- records `migratedFromVersion: 1` internally for user feedback;
- applies the resulting v2 session using the same validated import path as native v2 bundles.

The UI reports that migration occurred.

## Migration chain

Migrations are registered by source version and applied sequentially until the current version is reached. A future v3 implementation can therefore add a `v2 -> v3` migration without modifying the v1 migration.

If a required migration step is missing, import fails rather than guessing at schema semantics.

## Future-version policy

Bundles whose version is newer than the application supports are rejected with an explicit compatibility error. They are not silently interpreted as the current schema.

This prevents a newer bundle from being partially imported by an older Caching Tools release.

## Invalid/obsolete versions

- wrong bundle kind: rejected;
- non-integer version: rejected;
- version lower than the minimum supported version: rejected;
- invalid coordinates or malformed arrays: rejected;
- oversized bundles remain subject to the M1.53 4 MiB limit.

Import validation happens before live session state is replaced.

## Runtime qualification

Browser runtime tests cover:

- native v2 export;
- native v2 import;
- deterministic v1 -> v2 migration;
- migration status feedback;
- rejection of future bundle versions;
- rejection of invalid/obsolete bundles;
- existing 4 MiB file-size protection.
