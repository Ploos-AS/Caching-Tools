# M1.29 — Pause/resume and manual field markers

M1.29 extends the browser-side live field session with explicit recording control and manual field markers. It does not add server-side persistence, a new API, or a `/data` schema.

## Recording pause/resume

Live navigation and guidance continue while breadcrumb recording is paused. New geolocation positions still update the current coordinate and are still sent through the existing field-navigation API, but they are not added to the breadcrumb session while recording is paused.

Resuming recording starts a new recording segment. This is deliberate:

- travelled-distance statistics do not bridge the pause gap,
- timed-movement statistics do not count the pause interval as movement,
- GPX export emits a separate `<trkseg>` after each resume,
- quality filtering from M1.28 is still applied to each accepted breadcrumb.

The session duration remains wall-clock time from the first accepted breadcrumb to the latest accepted breadcrumb; timed movement excludes pause gaps.

## Manual markers

The user can add a marker at the current navigation coordinate at any time, including while breadcrumb recording is paused. Built-in marker types are:

- `cache`
- `trailhead`
- `note`
- `custom`

A custom marker type and an optional note can be supplied. Markers are kept only in browser memory for the current session, with a maximum of 500 markers. They are cleared when a new live session begins, on page reload, or explicitly with **Clear markers**.

## GPX export

Manual markers are exported as standard GPX 1.1 `<wpt>` elements with coordinate, timestamp, name, type and optional description. Breadcrumb recording segments are exported as separate `<trkseg>` elements under the session track.

M1.28 export simplification still applies, but it is performed separately within each recording segment. Manual markers are never simplified away.

## Asset order

The field-session layers are loaded in dependency order:

1. `field-navigation.js`
2. `field-quality.js`
3. `field-session.js`

This also makes the M1.28 quality layer part of the actual page runtime rather than only a served asset.

## Privacy and persistence

Pause state, breadcrumbs and manual markers remain browser-memory-only. Nothing in M1.29 is written automatically to `/data`, and no external provider is contacted by Caching Tools.

## Qualification

M1.29 is qualified by the existing Go test/vet/build CI plus static UI asset checks for pause/resume controls, segment-aware statistics/GPX generation, marker types, marker GPX waypoints and ordered loading of the quality/session assets.
