# M1.40 — richer local GPS map overlays

M1.40 makes the existing provider-neutral SVG map more useful in the field without adding map tiles, accounts, API keys or external network dependencies.

## Scope

The browser can optionally render these overlays on top of the existing saved waypoint/route/track map:

- waypoint labels;
- configurable waypoint-radius rings in metres;
- the current field-navigation coordinate;
- a guidance line from that coordinate to the waypoint selected on the map;
- the selected waypoint's field-navigation arrival radius.

The overlay layer is read-only. It does not alter saved waypoints, routes, tracks, field notes or navigation state.

## Projection semantics

The base map remains the existing schematic latitude/longitude SVG projection. Radius overlays convert metres to local latitude/longitude deltas and project those deltas through the same map projection. They are therefore useful visual field aids, not survey-grade geodesic circles.

## Local-first behavior

Overlay data comes only from the local `/api/waypoints` endpoint, the existing map selection event and the browser's field-navigation form. M1.40 adds no external map tiles, CDN resources, telemetry, provider integration or persistence.

## Acceptance

- `map-overlays.js` is served as a static asset and loaded after `map.js`.
- labels and radius rings can be independently toggled.
- waypoint radius is configurable in metres.
- the current field-navigation coordinate can be rendered on the map.
- selecting a waypoint can render a current-position-to-target guidance line.
- the target arrival-radius overlay follows the existing field-navigation arrival-radius value.
- overlays rerender after the base map emits `caching-tools:map-rendered` and after map selection changes.
- Go tests, vet and build remain green.
