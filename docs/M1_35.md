# M1.35 — Map / logbook integration

M1.35 connects the local SVG waypoint map with the persistent field-note logbook.

## Scope

- Selecting a waypoint on the local map opens a waypoint-specific logbook view.
- The logbook view shows only field notes whose `waypoint_id` matches the selected waypoint ID.
- A dedicated **New field note for selected waypoint** action resets the normal field-note editor and preselects the selected waypoint.
- The default new-note title includes the waypoint name for field convenience.
- After note CRUD/import refreshes the normal field-note list, the selected waypoint logbook refreshes automatically.

## Identity and linkage

Map integration uses the waypoint ID from the existing `caching-tools:map-select` event. It does not infer linkage from a waypoint name, so duplicate waypoint names remain unambiguous.

Field notes continue to use the existing soft `waypoint_id` reference introduced in M1.31. No persistent schema is changed.

## Local-first behavior

The integration reads the existing local APIs only:

- `GET /api/field-notes`
- existing waypoint map data already loaded by the map

Creating a note still uses the normal field-note CRUD workflow. M1.35 adds no provider calls, map tiles, telemetry, account dependency, or new persistence file.

## UI asset

`web/map-logbook.js` is loaded after `field-notes-dashboard.js`, which itself loads after `field-notes.js`. This ensures the normal field-note form helpers exist before the map logbook can prefill them.

## Acceptance

- waypoint map selection uses stable waypoint ID
- linked field notes render for the selected waypoint
- new field note action preselects the waypoint
- route/track selections do not alter the waypoint logbook
- selected waypoint logbook refreshes after note-list mutations
- no backend schema or persistence changes
- static UI regression covers the asset and loader chain
