# M1.31 — Persistent field notes / logbook

M1.31 adds a local persistent field log without changing the privacy model of live navigation sessions.

## Persistence

Field notes are stored in `/data/field-notes.json` by the same local-first pattern used by the other Caching Tools stores:

- JSON persistence under the configured `CACHING_TOOLS_DATA_DIR`
- mutex-protected reads/writes
- same-directory temporary file followed by rename
- UTC RFC3339Nano timestamps
- IDs in the form `note-<hex UnixNano>`

## Data model

Each note contains:

- title
- optional body
- optional status
- optional type
- optional `waypoint_id`
- optional `workspace_id`
- `occurred_at`
- created/updated timestamps

Waypoint and mystery-workspace references are intentionally soft local links rather than enforced foreign keys. A historical note therefore remains readable if the referenced object is later removed.

## API

- `GET /api/field-notes`
- `POST /api/field-notes`
- `GET /api/field-notes/{id}`
- `PUT /api/field-notes/{id}`
- `DELETE /api/field-notes/{id}`

The API rejects empty titles and invalid explicit `occurred_at` values. If `occurred_at` is omitted, the server uses the current UTC time.

## UI

The Field notes / logbook UI supports create, edit and delete operations. It can associate a note with an existing local waypoint and/or mystery workspace. Reference lists are loaded from the existing waypoint and workspace APIs.

## Privacy and scope

Field notes are persistent by explicit user action. Live breadcrumb sessions and unpromoted session markers remain ephemeral. M1.31 does not add cloud synchronization, provider APIs, accounts or external network dependencies.

## Qualification

M1.31 includes store round-trip tests, validation tests, HTTP CRUD tests and static UI asset checks.
