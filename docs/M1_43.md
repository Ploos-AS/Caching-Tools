# M1.43 — loader and rerender hardening

M1.43 hardens the dynamic browser asset chain used by the field-navigation, field-note and map-support tools.

## Problem

The previous loader functions reused existing `<script>` elements by attaching a new `load` listener. If the script had already completed loading before that listener was attached, the event would never fire again and the remaining loader chain could stop even though the asset itself was already ready.

## Solution

`map-link.js` now uses one idempotent `ensureDynamicAsset()` helper for the dynamic chain.

Each asset has:

- a stable `data-*` script marker;
- a local source path;
- a DOM readiness sentinel created by the asset itself;
- an optional next loader in the chain.

Before waiting for a script event, the helper checks the readiness sentinel. If it is already present, the next loader is scheduled immediately with `queueMicrotask()`.

Scripts created by the helper also track `data-loader-state` as `loading`, `loaded` or `failed`. A failed script is removed on the next request so a later attempt can retry instead of remaining permanently stuck.

## Hardened chain

The guarded chain covers:

1. field-quality
2. field-session
3. field-notes
4. field-note dashboard
5. map waypoint logbook
6. field-note attachments
7. field-note ZIP archive
8. attachment integrity

The independently loaded map editor now uses the same helper.

## Readiness sentinels

Examples include:

- `#field-quality-controls`
- `#field-session-controls`
- `#field-notes`
- `#field-note-dashboard`
- `#map-logbook`
- `#field-note-attachments`
- `#field-note-archive`
- `#field-note-attachment-integrity`
- `#map-path-editor`

These are local DOM objects created synchronously by their corresponding scripts, so they provide a direct indication that an already-loaded asset has executed.

## Compatibility

M1.43 changes no API, persistence format or navigation semantics. It only hardens browser orchestration. Existing static assets remain separate files and are still loaded on demand.

## Qualification

Static regression tests require the shared loader helper, loader-state handling, readiness sentinels, failed-load retry behavior and the absence of the old late-`load` listener patterns. Full Go test, vet and build qualification remains required.
